# GSK-KILO Component Adapters Specification

## Overview

The Adapter Layer serves as the foundational bridge between the **GSK-KILO Local Control Plane** and upstream external tooling:
1. **GenSpark CLI (`@genspark/cli`)**
2. **Kilo CLI (`@kilocode/cli`)**

Rather than executing ad-hoc shell commands across the codebase, all external CLI interactions and configuration generations are strictly encapsulated within dedicated adapter classes: GenSparkAdapter (src/adapters/genspark_adapter.js) and KiloAdapter (src/adapters/kilo_adapter.js).

---

## 1. GenSpark Adapter (`GenSparkAdapter`)

### 1.1 Architecture & Boundaries
The `GenSparkAdapter` interfaces with the official `@genspark/cli` binary without maintaining persistent child processes or creating unofficial proxies.

* **Binary Resolution**: Resolved via `CommandRunner.which('gsk')` across standard system paths and user npm-global prefix (`~/.npm-global/bin`).
* **Direct Execution**: Invokes official CLI commands (`gsk login-info`, `gsk login`, `gsk logout`, `gsk init-opencode`).
* **Credential Isolation**: GenSpark stores encrypted session tokens in `~/.genspark-tool-cli/config.json`. The control plane inspects user status exclusively via `gsk login-info` which outputs safe public profile metadata without exposing private API keys or bearer tokens.

### 1.2 Adapter Interface & Contract

| Method | Signature | Return Type | Description |
| :--- | :--- | :--- | :--- |
| `isInstalled()` | `static isInstalled(): { installed: boolean, path: string \| null }` | `Object` | Checks if `gsk` binary is found in PATH. |
| `getVersion()` | `static async getVersion(): Promise<{ version: string \| null }>` | `Promise<Object>` | Executes `gsk --version`. |
| `getLoginStatus()` | `static async getLoginStatus(): Promise<LoginStatus>` | `Promise<Object>` | Runs `gsk login-info` to fetch auth state, email, name, plan, personal/org plan, and credit balance. |
| `login(email, token)` | `static async login(email?: string, token?: string): Promise<LoginResult>` | `Promise<Object>` | Triggers GUI-friendly authentication flow. |
| `logout()` | `static async logout(): Promise<LogoutResult>` | `Promise<Object>` | Executes `gsk logout` and clears local catalog state. |
| `generateProviderConfig()` | `static async generateProviderConfig(): Promise<ConfigResult>` | `Promise<Object>` | Runs `gsk init-opencode` inside an isolated scratch sandbox to extract clean provider JSON. |
| `discoverProviders()` | `static async discoverProviders(): Promise<Provider[]>` | `Promise<Array>` | Parses `opencode.json` generated by official CLI. |
| `discoverModels()` | `static async discoverModels(): Promise<Model[]>` | `Promise<Array>` | Dynamically queries all models across all GenSpark providers. |
| `discoverEndpoints()` | `static async discoverEndpoints(): Promise<Endpoint[]>` | `Promise<Array>` | Discovers upstream HTTPS base URLs and proxy paths. |
| `passiveHealthCheck()` | `static async passiveHealthCheck(): Promise<HealthResult>` | `Promise<Object>` | Zero-cost health validation ($0 credit consumption). |
| `activeProbe(modelId)` | `static async activeProbe(modelId: string): Promise<ProbeResult>` | `Promise<Object>` | Explicit user-initiated single-token model request. |

## 2. Kilo Adapter (`KiloAdapter`)

### 2.1 Architecture & Isolation Invariant
Kilo CLI uses `$XDG_CONFIG_HOME/kilo/` as its configuration directory.
To prevent colliding with or corrupting any existing global `~/.config/kilo/` (which may contain legacy schema issues), `KiloAdapter` strictly enforces:

```bash
XDG_CONFIG_HOME=$HOME/.config/kilo-genspark
```

### 2.2 Adapter Interface & Contract

| Method | Signature | Return Type | Description |
| :--- | :--- | :--- | :--- |
| `isInstalled()` | `static isInstalled(): { installed: boolean, path: string \| null }` | `Object` | Checks if `kilo` binary is found in PATH. |
| `getVersion()` | `static async getVersion(): Promise<{ version: string \| null }>` | `Promise<Object>` | Executes `kilo --version`. |
| `getAuthStatus()` | `static async getAuthStatus(): Promise<AuthStatus>` | `Promise<Object>` | Executes `kilo auth list` in isolated runtime. |
| `getConfigStatus()` | `static getConfigStatus(): ConfigStatus` | `Object` | Validates syntax and provider structure of `kilo.json`. |
| `getModels()` | `static async getModels(): Promise<ModelList>` | `Promise<Object>` | Executes `kilo models` with isolated runtime. |
| `getProviders()` | `static getProviders(): ProviderList` | `Object` | Reads configured providers from isolated `kilo.json`. |
| `health()` | `static async health(): Promise<HealthResult>` | `Promise<Object>` | Validates Kilo binary, isolated config, and providers. |

## 3. Dynamic Catalog Synchronization (`CatalogSync`)

The `CatalogSync` service orchestrates synchronization between GenSpark CLI outputs and the local SQLite database (`control.db`).

### 3.1 Data Flow
```text
GenSpark CLI (`gsk init-opencode`)
        │
        ▼ (isolated scratch space)
opencode.json (Temporary AST)
        │
        ▼
CatalogSync.syncCatalog()
        ├──> UPDATE providers table (genspark-llm-proxy, genspark-gemini-proxy)
        ├──> UPDATE endpoints table (https://www.genspark.ai/api/llm_proxy/v1, etc.)
        └──> UPSERT models table (36+ dynamic models with context limits & modalities)
```

### 3.2 Dynamic Catalog Schema
Catalog queries do **not** rely on hardcoded counts or static arrays. The database dynamically stores:
- `provider_id`: Unique provider identifier.
- `model_id`: Full model string (`genspark-llm-proxy/claude-sonnet-4-6`).
- `display_name`: Human-readable title.
- `context_window`: Context tokens (e.g. 200,000).
- `input_modalities`: Comma-separated modalities (`text,image`).
- `output_modalities`: Comma-separated output formats (`text`).
- `status`: Active / Deprecated.
